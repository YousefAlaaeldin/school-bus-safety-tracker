# Phase 3 — Push notifications, parent app, live bus tracking

Goal:
- Notifications queued in Phase 2 actually reach parents' phones, in their language.
- The helper's phone streams GPS in the background.
- Parents watch the bus live on a map while their child is on it (or while it's coming, in the morning).

### T3.05 — Edge Function `notify-dispatch` ⚠ hard
- **Depends:** T3.02, T3.03, T3.04
- **Read:** i18n.md §5, §6; rpc.md §5 (claim/complete); app-routes-env §6 (`PUSH_MOCK`, `EXPO_ACCESS_TOKEN`)
- **Files:** `supabase/functions/notify-dispatch/index.ts`, `supabase/functions/_shared/dispatch.ts`, `supabase/functions/_shared/dispatch.test.ts`
- **Steps:**
  1. **`dispatch.ts`** (pure, testable): `buildMessages(rows, messagesByLocale)` → for each row × token, a `PushMessage`:
     - `title`/`body` from `renderNotification(messages[locale], row.type, locale, row.params)`
     - `data = {type, trip_id, student_id, notification_id: row.id}`
     - `channelId 'safety'`, `priority 'high'`, `sound 'default'`, `interruptionLevel 'time-sensitive'`

     Rows with no tokens produce no messages and are reported as `NO_TOKENS`.
  2. **`index.ts`** (Deno):
     - `Deno.serve` creates a supabase-js client with the service role (`jsr:@supabase/supabase-js@2`, or `npm:`; follow the current Supabase Edge Functions docs)
     - loops up to 5 times: `claim_due_notifications(100)` → build → send (or, if `PUSH_MOCK=1`, fake tickets `mock-<uuid>`) → `complete_notification` per row:
       - all tickets `ok` → `sent`
       - `NO_TOKENS` → `failed`
       - an HTTP error → `pending`
     - stops early if a claim returns 0 rows
     - imports the JSON with `import en from './../_shared/i18n/en.json' with { type: 'json' };` (and the same for `ar`)
     - returns `{processed}`
- **Tests:** `buildMessages` produces 2 messages for 1 row with 2 tokens, picks the Arabic title for an `ar` recipient, and reports `NO_TOKENS`.
- **Done when:** `pnpm test` passes. Then, manually: `supabase functions serve notify-dispatch --env-file supabase/functions/.env` and `curl -X POST http://localhost:54321/functions/v1/notify-dispatch -H "Authorization: Bearer <service_role_key>"` returns `{processed: …}`.
- **Stop if:** JSON import attributes aren't supported by the local Edge runtime. Then generate a `messages.ts` that exports the objects instead (update T3.02's script), and note it.

### T3.06 — Cron schedules + local Vault secrets
- **Depends:** T3.05
- **Read:** skeletons §4
- **Files:** `supabase/migrations/20260101003100_cron_jobs.sql`, `supabase/seed.sql`
- **Steps:**
  1. In the migration, schedule:
     - `notify-dispatch` every `'10 seconds'` (HTTP)
     - `generate-trips` at `'30 0 * * *'` (00:30 UTC = 04:30 Dubai) running `select public.generate_trips((now() at time zone 'Asia/Dubai')::date); select public.generate_trips((now() at time zone 'Asia/Dubai')::date + 1);`
  2. Wrap each `cron.schedule` so re-running is safe: `select cron.unschedule(jobname) from cron.job where jobname = '...';` first.
  3. In `seed.sql` (local only), append `select vault.create_secret('<local api url reachable from db container>', 'project_url');` and the same for `service_role_key`, with the local key from `supabase status`. Comment: `-- LOCAL DEMO VALUES ONLY`.
- **Done when:** `pnpm db:reset` succeeds, and `select jobname, schedule from cron.job` lists both jobs. With `supabase functions serve` running, a row inserted into `notification_outbox` (with `PUSH_MOCK=1`) becomes `sent` within about 20 s.
- **Stop if:** any of skeletons §4's Stop-if conditions apply.

### T3.07 — Edge Function `push-receipts` + cron

### T3.11 — Parent live map
- **Depends:** T3.10, T2.23

  4. Never show other children's stops.

### H3.1 — Device test: background tracking and push 👤
Run with two real phones (a helper and a parent), local Supabase reachable over LAN, `PUSH_MOCK=0`, and a development build.
1. Sign in the parent as +971500000003 and the helper as +971500000002. Generate trips for today in Studio.
2. **Helper:** start A_PM, board STUDENT_1. Within about 20 s, the parent gets "Sara is on the bus" in their language.

4. **Helper:** lock the screen and walk or drive about 500 m. The parent's map moves. On Android, the "Trip in progress" notification is visible.
5. **Helper:** drop STUDENT_1 → the parent gets "dropped off" and the map shows "Tracking has ended".
6. **Mis-tap:** board, then un-board within 10 s → the parent gets **nothing**.
7. Repeat steps 2–5 with the parent's language set to the other language.
8. **Admin:** sign in a third phone as `admin-a@example.com`. Confirm roll call with someone missing → the admin phone gets the alert push.

Write the results in `BLOCKED.md` → "Device checks".
