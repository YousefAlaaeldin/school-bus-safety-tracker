# Phase 1a — Database foundation

Goal: the full schema, access rules (RLS), seed data and tests. After this phase, `pnpm db:reset && pnpm db:test` is green and proves that parents can't see other people's children.

General rules for every task in this file:
- Migration file names are fixed. Create **exactly** the named file.
- After writing a migration, run `pnpm db:reset`. It must succeed.
- `security definer` functions use `set search_path = ''` and fully-qualified names.

### T1.16 — Seed data
- **Depends:** T1.15
- **Read:** data-model §5 (all of it), §2 (columns)
- **Files:** `supabase/seed.sql`
- **Steps:**
  1. Insert the users into `auth.users`. The trigger creates their profiles. Columns:
     - `id`, `instance_id = '00000000-0000-0000-0000-000000000000'`, `aud = 'authenticated'`, `role = 'authenticated'`
     - `email` or `phone`. **Phone without the `+`**, e.g. `'971500000003'`.
     - `phone_confirmed_at` / `email_confirmed_at = now()`, `created_at`, `updated_at = now()`
     - `raw_app_meta_data = '{"provider":"phone","providers":["phone"]}'`, or `email` for the admins
     - `raw_user_meta_data = '{}'`
     - For admins: `encrypted_password = extensions.crypt('password123', extensions.gen_salt('bf'))`
  2. For admins, also insert matching `auth.identities` rows if email login fails without them (check by logging in at T1.54).
  3. Insert the schools, memberships, buses, stops (`extensions.st_setsrid(extensions.st_makepoint(lng, lat), 4326)::extensions.geography`), routes, route_schedules, route_stops, students, assignments, and guardian_links with the given statuses.
  4. Set `display_name` on the profiles, e.g. "Helper A", "Parent 1".
- **Done when:** `pnpm db:reset` succeeds, and `select count(*) from public.profiles` returns 9 (check in Studio → SQL editor at `http://localhost:54323`).
- **Stop if:** inserting into `auth.users` fails. Paste the error.

### T1.21 — RPCs: invites, guardian approval, staff ⚠ hard
- **Depends:** T1.20
- **Read:** rpc.md §Errors, §2 (`create_invite`, `redeem_invite`, `approve_guardian_link`, `revoke_guardian_link`, `invite_staff`, `remove_staff`, `acknowledge_alert`, `set_trip_helper`)
- **Files:** `supabase/migrations/20260101001800_rpc_invites_staff.sql`, `supabase/tests/210_invites_staff.test.sql`
- **Assertions:**
  - ADMIN_A creates an invite for STUDENT_5's `+971500000099` link (no user yet), gets an 8-character code; PARENT_2 redeems it → that link is approved with `guardian_user_id = PARENT_2`, and PARENT_2 now sees STUDENT_5
