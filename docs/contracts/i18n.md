# Contract: i18n (Arabic + English)

## §1 Files
```
packages/i18n/src/en.json      English messages
packages/i18n/src/ar.json      Arabic messages (same keys)
packages/i18n/src/format.ts    formatTime, formatDate, isolate
packages/i18n/src/render.ts    renderNotification
packages/i18n/src/index.ts     re-exports + `resources` object for i18next
```
- Both JSON files have **identical key sets**. A vitest test (`parity.test.ts`) fails if a key is missing on either side, or if the `{{placeholders}}` differ.
- Placeholders use i18next syntax: `{{name}}`.

## §2 Key naming
Keys are nested, with these top-level namespaces only:

| namespace | used for |
|---|---|
| `common` | Buttons and words used everywhere: `common.ok`, `common.cancel`, `common.retry`, `common.save`, `common.loading`, `common.back`, `common.signOut`, `common.language`, `common.arabic`, `common.english` |
| `welcome` | Mobile landing screen |
| `auth` | Phone / OTP screens |
| `onboarding` | Invite, pending, not-registered, choose-role |
| `settings` | Settings screen |
| `helper` | All helper-mode screens |
| `admin` | Mobile admin alerts mode |
| `parent` | All parent-mode screens |
| `permissions` | Location / notification permission explainers |
| `landing` | Web landing page |
| `legal` | Privacy / terms / support pages |
| `dashboard` | Web dashboard |
| `status` | One key per `student_trip_status` and `trip_status` value, e.g. `status.student.boarded`, `status.trip.in_progress` |
| `errors` | One key per RPC error code from `rpc.md` §Errors (e.g. `errors.PAST_CUTOFF`), plus `errors.NETWORK` and `errors.UNKNOWN` |
| `notif` | Push notification templates (§4). **Frozen; do not change their wording without a human** |

Keys use camelCase: `helper.rollCall.confirmButton`.

## §3 Formatting (`format.ts`)
Formatting must be pure TS with **no imports**, so the same file runs in Node, React Native and Deno.

```ts
export type Locale = 'ar' | 'en';
export const TIME_ZONE = 'Asia/Dubai';

/** "3:07 PM" / "3:07 م". Western digits always. */
export function formatTime(iso: string, locale: Locale): string;
// implementation: new Intl.DateTimeFormat(locale === 'ar' ? 'ar-AE-u-nu-latn' : 'en-AE',
//   { hour: 'numeric', minute: '2-digit', hour12: true, timeZone: TIME_ZONE }).format(new Date(iso))

/** "Mon 7 Jan" / "الاثنين 7 يناير". Western digits always. */
export function formatDate(isoOrDate: string, locale: Locale): string;
// weekday: 'short', day: 'numeric', month: 'short', same locale tags and time zone

/** Wraps text in Unicode FSI…PDI (⁨ … ⁩) so numbers/Latin text don't scramble inside Arabic. */
export function isolate(text: string): string;
```

## §5 Notification params → placeholders (`render.ts`)

```ts
export type NotificationParams = {
  child_ar?: string; child_en?: string;
  bus_ar?: string;   bus_en?: string;
  stop_ar?: string;  stop_en?: string;
  names_ar?: string; names_en?: string;
  time_iso?: string; minutes?: number; count?: number; reason?: string;
};
export type Messages = Record<string, unknown>; // the parsed en.json / ar.json

/** Pure. No imports except ./format. Throws if the template key is missing. */
export function renderNotification(
  messages: Messages, type: string, locale: Locale, params: NotificationParams
): { title: string; body: string };
```

Placeholder resolution:
| placeholder | value |
|---|---|
| `child`, `bus`, `stop`, `names` | `params[`${p}_${locale}`] ?? params[`${p}_${other}`] ?? ''` |
| `time` | `params.time_iso ? formatTime(params.time_iso, locale) : ''` |
| `minutes`, `count` | `String(value ?? '')` |
| `reason` | `params.reason ?? ''` |

In `ar`, every substituted value except `names` is wrapped with `isolate()`.

## §6 Push payload `data`
Every push carries `data: { type, trip_id, student_id, notification_id }`. Values are strings, or null for missing. The mobile app routes taps with this (see `app-routes-env.md` §3).
